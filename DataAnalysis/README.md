# TongliDataAnalysis.py — GPS 轨迹数据延时/丢失分析工具

对 MDVR（车载终端）上报的轨迹 Excel/CSV 做批量质量分析：逐行算出**延时**、判断**丢失**、识别**重发**，并把结果写回带颜色的 Excel，同时在控制台打印各项统计与占比。

- 输入：Excel / CSV 轨迹数据（含 `卫星时间`、`接收时间`、`车辆状态(ACC)`，可选 `GNSS信号`）
- 输出：`<原文件名>_分析.xlsx`，新增 3 列并标色，列宽自适应，首行冻结
- 规模：实测 18422 行约 13 秒；5 万行约 13 秒（纯计算 0.07 秒，主要耗时在写 xlsx）

## 2. 使用方式

### 方式 A：双击运行（推荐给非开发人员）
直接运行脚本，依次弹出：
1. 选择文件对话框 → 选轨迹 Excel/CSV
2. 「ACC 开 间隔阈值」输入框（默认 15 秒）
3. 「ACC 关 间隔阈值」输入框（默认 120 秒）

结果输出到源文件同目录，文件名 `<原文件名>_分析.xlsx`。

### 方式 B：命令行

```bash
# 全部参数走命令行，不弹窗
python TongliDataAnalysis.py --input "轨迹信息 (7).xlsx" --acc-on 15 --acc-off 120

# 只指定输入，阈值走弹窗
python TongliDataAnalysis.py --input "轨迹信息 (7).xlsx"

# 指定输出路径
python TongliDataAnalysis.py --input in.xlsx --acc-on 15 --acc-off 120 --output out.xlsx
```

### 参数说明

| 参数 | 必填 | 说明 |
|---|---|---|
| `--input` | 否 | 输入 xlsx/xls/csv；不填则弹窗选择 |
| `--acc-on` | 否 | **ACC 开**时相邻上报允许的最大间隔（秒），默认 15，不填则弹窗 |
| `--acc-off` | 否 | **ACC 关**时相邻上报允许的最大间隔（秒），默认 120（2 分钟），不填则弹窗 |
| `--output` | 否 | 输出路径；默认 `<输入文件名>_分析.xlsx` |

> 建议命令行同时给 `--acc-on` 和 `--acc-off`，避免脚本在无人值守环境弹窗卡住。

## 5. 判定规则详解

### 5.1 延时（新增列）

```
延时 = 接收时间 − 卫星时间
```

- **不做任何阈值过滤**，每行都算，不管延时多长（0 秒、几小时、几天）都写进「延时」列
- 保留符号：`接收 < 卫星` 时为负值（说明数据时间回跳 / 设备时钟异常 / 补传乱序）
- 格式 `±H:MM:SS`，四舍五入到秒
- 任一时间缺失或解析失败 → 该行留空
- 实现：`fmt_hms_series()` 向量化生成（numpy/pandas 批量拼接），5 万行约 0.07 秒

### 5.2 丢失（新增列，按 ACC 分档）

核心：**ACC 开 和 ACC 关 允许的上报间隔不同**，两个阈值由弹窗/命令行给。

```
gap = 当前行卫星时间 − 上一行卫星时间（秒）
limit = ACC 状态为「关」 ? acc_off_sec : acc_on_sec
gap > limit  →  丢失
gap ≤ limit  →  正常
```

- **用哪一行的 ACC 判定？** 用**当前行**（即这条上报发生时车辆的状态）
- 每段的第一行（无上一行）留空，判不了
- 示例（ACC 开 15s / ACC 关 120s）：

| 间隔 | ACC 状态 | 结果 | 说明 |
|---|---|---|---|
| 10s | 开 | 正常 | < 15 |
| 20s | 开 | 丢失 | > 15 |
| 30s | 关 | 正常 | 关档 30 < 120 |
| 180s | 关 | 丢失 | > 120 |

**ACC 值解析规则**（`parse_acc`）：

- 优先提取 `ACC` 后紧跟的状态词，如 `ACC 开 ,左转向灯信号` → 开，`ACC 关` → 关（避免转向灯等附加状态干扰）
- 兼容：`开/关`、`ON/OFF`、`1/0`、`true/false`、`open/close`
- **无法识别的值按「开」处理**（用更严的 15s 阈值，宁多报不漏报）

### 5.3 重发（新增列）

```
当前行卫星时间 == 上一行卫星时间  →  重发
```

- 按**当前行顺序**逐行与上一行比对，连续重复会逐条标记（如 3 行同时间 → 第 2、3 行都标「重发」）
- 首行留空
- 数据未按时间排序时可能漏判，可用 `analyze(..., sort_by_time=True)` 先排序（默认关闭）

### 5.4 定位统计（仅控制台，不写列）

从定位状态列（`GNSS信号` 等）解析：

- **未定位**：值含 `未 / 无 / 不 / 失效 / 无效 / invalid / nofix`，或为 `0 / V / false / n / no`
- **已定位**：其余（含 `定位 卫星数(6)`、`A`、`1`）
- 列不存在时：打印一行提示并跳过，不影响其他分析

## 8. 常见问题

**Q：报 `PermissionError: [Errno 13]`？**
输出文件正被 Excel/WPS 打开。脚本已内置兜底：自动改存带时间戳的新文件并提示。想覆盖原文件就关掉它再跑。

**Q：报「未找到 ACC/车辆状态列」？**
输入文件缺少 ACC 列，或不叫这些名字。按报错里列出的现有列名，改脚本顶部 `ACC_COL_CANDIDATES`。

**Q：定位统计没打印？**
没找到定位状态列，脚本会提示后跳过。改 `POS_COL_CANDIDATES` 补上实际列名（如 `GNSS信号`）。

**Q：为什么丢失全算在「ACC 开」档？**
统计按当前行 ACC 状态归类。这批数据绝大多数是 ACC 开（如 18422 行中仅 55 行 ACC 关），自然以开档为主。

**Q：ACC 关的阈值想按分钟输入？**
阈值单位固定为秒，2 分钟就填 `120`。

**Q：想按上一行的 ACC 状态判？**
改 `analyze()` 里 `acc_state = parse_acc(df[acc_col])` 为 `acc_state = parse_acc(df[acc_col]).shift(1).fillna("on")`。
